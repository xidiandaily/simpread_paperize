# Feature Specification: SR Book CLI（成书 / 多卷合集 PDF）

**Feature Branch**: `003-sr-book-cli`

**Created**: 2026-05-16

**Status**: Draft

**Input**: User description: "新增 CLI「成书」能力，命令名 sr_book，与现有 sr_paperize（HTML→单篇 PDF）互补：在**不修改、不覆盖**用户已有单篇 PDF 内容的前提下，依据 manifest 将多篇 PDF 编排为多卷「合集 PDF」，供个人打印与电子阅读。子命令（必须四个）：init、index、plan、build。【init】在指定目录生成 manifest 模板（YAML），包含全书元数据、分卷与篇目占位；用户手改 manifest 为唯一编排来源。【index】严格按 manifest 中篇目顺序，对磁盘上的 PDF 文件添加数字前缀重命名（如 1_、2_…）。重命名后 MUST 回写 manifest 内对应路径，保证后续 plan/build 路径有效。支持 --dry-run 仅打印将执行的重命名而不改文件。不得覆盖非 PDF 或 manifest 未列出的文件。【plan】读取 manifest 与各篇 PDF 页数（及封面 PDF 页数、打印目录页数等），计算每卷分页、每篇在合集中的物理起始页、是否超每卷页数上限；输出人类可读表格，并输出 JSON；支持将结果写入与 manifest 同目录的 plan.json（路径可配置时默认此约定）。不得写入最终合集 PDF。若校验失败（如封面缺失、单篇页数超过每卷上限导致无法整篇入卷）须非零退出并给出可行动错误信息。【build】依据 manifest 与 plan 阶段一致的规则生成每卷合集 PDF：每卷开头为 manifest 写死的封面 PDF 路径；封面文件缺失则报错退出并提示用户补封面。随后插入可打印目录页（版式实现自定），再按顺序合并各篇 PDF。**不修改**源单篇 PDF 文件；仅写新输出文件。合集内：页眉使用 manifest 中给定的批次/追溯字符串（如 lawrencechi_bookcase_20260514，整串由用户配置）；左下角叠加「当前页/该卷总页数」，按卷重置；单篇 PDF 内原有右下角页码等内容保持不变。书签（outline）仅保留「篇级」一层，子 PDF 原有书签全部丢弃。打印目录条目仅包含「篇名 + 该篇在合集中的物理起始页」；封面与目录页本身不作为目录中的行。目录中的起始页为**合集中物理页码**（含封面从第 1 页起算），与阅读器页码一致。【分卷规则】每卷总页数不得超过 manifest 配置的 max_pages_per_volume（默认 400，含义为合集 PDF 物理页数，含封面与目录页）。不得从某篇文章中间切卷；若当前卷加入下一篇会超限，则将该篇整篇移到下一卷。若某一篇文章自身页数大于 max_pages_per_volume，plan MUST 报错，提示用户拆篇或提高上限（不允许静默超上限）。【路径】manifest 内路径一律为相对路径，相对 manifest 文件所在目录解析。【隐私与离线】全本地处理；日志与错误信息不得回传正文；不读取网络。若需临时文件，写入用户可配置输出目录或系统临时目录并在文档中说明。成功标准（验收层面）：维护者可仅通过四子命令与编辑 manifest 完成「编号→校验→成书」闭环；plan 与 build 在相同 manifest 下对页码与分卷结论一致；缺失封面或无法分卷时失败可复现且信息明确。"

> **Paperize 语境**: 本功能全本地、离线执行；不得通过网络回传日志或错误中的正文内容；不得修改用户已有单篇 PDF 源文件；临时与中间产物写入用户可配置目录或系统临时区，并在随附文档中说明，以降低隐私外泄风险。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初始化成书工程与编排契约 (Priority: P1)

维护者希望在空目录或既有篇目目录中快速建立「成书」编排契约：运行初始化子命令后得到一份 YAML manifest 模板，内含全书元数据、分卷与篇目占位；之后仅通过手改 manifest 驱动全书结构，无需其他隐式配置源。

**Why this priority**: 没有稳定 manifest 契约，后续编号、分页与成书均无法复现或协作。

**Independent Test**: 在指定目录执行初始化后，存在符合约定的 manifest 模板，字段足以支撑后续子命令；不依赖网络。

**Acceptance Scenarios**:

1. **Given** 用户选定一目标目录，**When** 执行初始化子命令，**Then** 在该目录生成 YAML manifest 模板，包含全书元数据、分卷与篇目占位结构。
2. **Given** 用户已生成模板，**When** 仅编辑 manifest 指定篇目相对路径、封面、追溯字符串与分卷参数，**Then** 再执行后续子命令时，工具以 manifest 为唯一编排来源解析配置。

---

### User Story 2 - 篇目顺序编号与 manifest 路径同步 (Priority: P2)

维护者希望严格按 manifest 中篇目顺序，为磁盘上的各篇 PDF 添加数字前缀（如 `1_`、`2_`…），并在重命名后自动回写 manifest 中的对应路径，以便 plan/build 始终引用有效路径；在正式执行前可用仅预览模式核对将发生的重命名。

**Why this priority**: 路径与磁盘一致性是「校验→成书」链路的前置条件，错误重命名会破坏后续分页与合并。

**Independent Test**: 准备若干 PDF 与 manifest 列表，执行仅预览与真实执行两种路径，检查重命名集合、manifest 回写及未列出文件未被触碰。

**Acceptance Scenarios**:

1. **Given** manifest 列出多篇 PDF 的相对路径且文件存在，**When** 执行编号子命令（非仅预览），**Then** 文件按 manifest 顺序获得数字前缀重命名，且 manifest 内路径被回写为与实际文件名一致。
2. **Given** 同一 manifest，**When** 执行带仅预览标志的编号子命令，**Then** 终端输出将执行的重命名列表，磁盘文件与 manifest 均不改变。
3. **Given** 目录中存在未在 manifest 列出的 PDF 或其它类型文件，**When** 执行编号子命令，**Then** 仅处理 manifest 列出且扩展名为 PDF 的条目，不覆盖、不重命名未列出或非 PDF 文件。

---

### User Story 3 - 分页规划、校验与可机器消费的计划产物 (Priority: P3)

维护者希望在生成合集前，一次性获知每卷页数、每篇在合集中的物理起始页、是否违反每卷页数上限；输出既有人类可读表格又有结构化计划文件；校验失败时以非零退出码结束并给出可行动说明。规划阶段不得写出最终合集 PDF。

**Why this priority**: 提前发现无法分卷或封面缺失等问题，避免浪费时间与磁盘在错误配置上成书。

**Independent Test**: 构造合法与非法 manifest（缺封面、单篇超过每卷上限等），检查退出码、错误文案、表格与结构化输出；确认未生成合集 PDF。

**Acceptance Scenarios**:

1. **Given** manifest 与各篇、封面路径有效且可分卷，**When** 执行规划子命令，**Then** 输出包含每卷页数、每篇物理起始页、是否触及上限等信息的表格，并输出与之一致的结构化计划；可选地将计划写入与 manifest 同目录的默认计划文件，或通过配置指定路径。
2. **Given** 封面缺失或某篇文章页数大于配置的每卷最大物理页数导致无法整篇入卷，**When** 执行规划子命令，**Then** 进程以非零退出码结束，错误信息明确提示补封面、拆篇或提高上限等可操作项。
3. **Given** 规划子命令成功，**When** 检查输出目录，**Then** 不存在最终合集 PDF 文件被创建。

---

### User Story 4 - 按规划成书：多卷合集、版式叠加与篇级书签 (Priority: P4)

维护者希望在规划通过后，依据 manifest 与同套分卷规则生成每卷合集 PDF：每卷以 manifest 指定的封面起头，缺封面则失败退出；其后为可打印目录页，再按序合并各篇；源单篇 PDF 不被修改。合集内页眉展示用户配置的批次/追溯整串；左下角显示「当前页/该卷总页数」且按卷重置；单篇内既有页码等版式保留。书签层级仅保留到「篇」，子文档原有书签丢弃。打印目录仅列篇名与各篇在合集中的物理起始页（封面与目录页不出现在目录行中），起始页从合集物理第 1 页起算并与阅读器页码一致。

**Why this priority**: 这是面向打印与电子阅读的交付形态，直接体现产品价值。

**Independent Test**: 使用与规划阶段相同的 manifest，对比规划输出的起始页/分卷与成书结果；抽样用阅读器检查物理页码、页眉、角标、书签层级与目录行内容。

**Acceptance Scenarios**:

1. **Given** 规划成功且封面文件存在，**When** 执行成书子命令，**Then** 生成各卷新合集 PDF 文件，且任一源单篇 PDF 的字节级内容与修改时间不被工具改写（除用户另行手工操作外）。
2. **Given** manifest 中写明的封面路径在磁盘上不存在，**When** 执行成书子命令，**Then** 失败退出并提示用户补全封面。
3. **Given** 成书成功，**When** 用阅读器打开合集，**Then** 页眉为 manifest 配置的追溯整串；左下角为「当前页/该卷总页数」；打印目录行为篇名 + 该篇物理起始页，且不包含封面行与目录页自身行；书签仅一层篇级。

---

### Edge Cases

- manifest 内路径为相对路径：解析基准为 manifest 文件所在目录；目标文件被移走或重命名后路径失效时的明确报错。
- 当前卷剩余空间不足以容纳下一整篇：下一篇整篇移入下一卷，不在篇中断开。
- 单篇页数大于 `max_pages_per_volume`：规划必须失败并提示拆篇或提高上限，不得静默超出。
- 编号子命令中途失败（磁盘满、权限、重名冲突）：应尽可能不留下半套不一致状态，或文档说明恢复/重试策略（以可测试的验收为准）。
- 仅预览模式与真实模式行为边界：仅预览不得产生任何磁盘或 manifest 变更。
- 日志与错误信息：不得包含通过网络外传的步骤；不得将用户文档正文嵌入遥测（本功能假定无网络读取与无回传正文）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 产品 MUST 提供名为 `sr_book` 的命令行入口，与既有「单篇 HTML→PDF」工作流互补定位；不得将成书流程实现为对用户已有单篇 PDF 的就地改写或静默覆盖。
- **FR-002**: `sr_book` MUST 暴露且仅暴露四个一级子命令：`init`、`index`、`plan`、`build`；不得用其它子命令替代上述四步闭环。
- **FR-003**: `init` MUST 在用户指定目录生成 YAML manifest 模板，包含全书元数据、分卷结构及篇目占位；用户手改后的 manifest MUST 成为后续子命令的唯一编排来源（除各子命令显式接受的 CLI 标志外无第二配置源）。
- **FR-004**: `index` MUST 严格按 manifest 中篇目顺序，为已存在的各篇 PDF 文件添加数字前缀重命名；重命名完成后 MUST 将 manifest 中对应篇目路径回写为与实际文件名一致，以保证 `plan`/`build` 引用有效。
- **FR-005**: `index` MUST 支持仅预览标志：在此模式下打印将执行的重命名操作列表，且不得修改磁盘文件也不得修改 manifest。
- **FR-006**: `index` MUST 仅处理 manifest 中列出且为 PDF 的条目；不得重命名、覆盖或删除未列出文件，不得对非 PDF 扩展名执行编号逻辑。
- **FR-007**: `plan` MUST 读取 manifest，并统计各篇 PDF、封面 PDF、以及成书时将插入的打印目录页的页数参与分页模型；计算每卷总物理页数、每篇在合集中的物理起始页、是否违反每卷页数上限；将关键结果以人类可读表格形式输出，并输出与表格语义一致的结构化（JSON）结果。
- **FR-008**: `plan` MUST 支持将结构化结果写入文件；默认约定为与 manifest 同目录的 `plan.json`，若用户通过配置覆盖输出路径，则以用户配置为准。
- **FR-009**: `plan` MUST NOT 写入或替换最终合集 PDF；成功路径下亦不得提前生成成书产物。
- **FR-010**: 当校验失败（示例性非穷尽：封面缺失、任一单篇页数大于 `max_pages_per_volume` 导致无法整篇入任一卷、或其它 manifest/文件不一致）时，`plan` MUST 以非零退出码结束，并给出可行动的终端错误说明（例如补封面、拆篇、调整上限、修正路径）。
- **FR-011**: `build` MUST 使用与 `plan` 相同的 manifest 字段及分卷、分页规则生成各卷合集 PDF；不得修改或覆盖源单篇 PDF；仅允许写入新的合集输出文件（及文档已说明的临时/中间文件，若有）。
- **FR-012**: 每卷合集 MUST 以 manifest 中该卷写明的封面 PDF 为起始内容；若封面文件缺失，`build` MUST 失败退出并提示用户补封面。
- **FR-013**: 封面之后 MUST 插入可打印目录页（具体版式由实现决定，验收以「可读、可打印、符合下列目录语义」为准），再按 manifest 篇目顺序合并各篇 PDF。
- **FR-014**: 合集页眉 MUST 完整展示 manifest 中用户配置的批次/追溯字符串（示例形态如 `lawrencechi_bookcase_20260514`，实际字串以用户配置为准）。
- **FR-015**: 合集左下角 MUST 叠加「当前物理页 / 该卷总物理页」，计数在每卷内从该卷第 1 页重新起算；不得要求改动单篇 PDF 内已有页码或角标内容。
- **FR-016**: 合集书签（大纲）MUST 仅保留「篇」级一层；来自各子 PDF 的更深层书签 MUST 全部丢弃。
- **FR-017**: 打印目录条目 MUST 仅包含「篇名」与「该篇在合集中的物理起始页」；不得将封面页或目录页自身作为目录中的行；目录中的页码 MUST 为从合集物理第 1 页起算的页码，并与常见阅读器中展示的页码一致。
- **FR-018**: 分卷规则：每卷总物理页数不得超过 manifest 中的 `max_pages_per_volume`，默认值为 400；计数包含封面与目录页；不得对单篇文章跨卷截断；若将下一整篇并入当前卷会超限，则该篇整篇移至下一卷。
- **FR-019**: 若某一单篇 PDF 的页数本身大于 `max_pages_per_volume`，`plan` MUST 报错，并提示用户拆篇或提高上限；禁止静默生成超上限的卷。
- **FR-020**: manifest 中出现的文件路径 MUST 为相对路径，并相对于 manifest 文件所在目录解析。
- **FR-021**: 全流程 MUST 在本地离线执行；不得读取网络资源；日志与错误信息 MUST NOT 将用户文档正文回传到外部服务（本规格假定无此类通道）。
- **FR-022**: 若实现需要临时或中间文件，MUST 支持或可配置写入用户指定输出目录，否则使用系统临时目录；该行为 MUST 在随附用户文档中说明，便于隐私与磁盘治理。

### Key Entities

- **Manifest（YAML）**: 全书元数据、分卷定义、各卷封面路径、篇目列表（显示名与相对路径）、批次/追溯字符串、`max_pages_per_volume` 等；唯一编排源。
- **篇目条目**: 指向磁盘上某单篇 PDF 的相对路径与在合集中显示的篇名；参与顺序编号与合并顺序。
- **规划结果（结构化）**: 每卷边界、每卷总页数、每篇物理起始页、校验状态与错误码语义；与 `plan` 表格输出一致，并可持久化为 `plan.json`（或等效可配置路径）。
- **卷（Volume）**: 逻辑上连续的一组篇，受 `max_pages_per_volume` 约束；对应一个输出合集 PDF（除规划阶段外）。
- **合集 PDF**: 面向打印/阅读的最终每卷文件；包含封面、目录页、合并正文与版式叠加规则产物。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一名熟悉文档的维护者可在不依赖网络的情况下，仅通过四个子命令与编辑 manifest，完成从「篇目编号 → 分页校验 → 生成多卷合集」的端到端闭环，中途无需未文档化的隐藏步骤。
- **SC-002**: 对同一 manifest 与未改动的源 PDF 集，规划子命令输出的每篇物理起始页与分卷划分，与随后成书子命令实际生成的合集页面对应关系一致；抽样核对至少三篇跨卷场景仍一致。
- **SC-003**: 在封面缺失或规划已判定不可分卷（含单篇超每卷上限）情形下，重复执行对应子命令时，失败结果稳定可复现（相同输入下退出码与错误要点一致），且错误信息能让维护者在不阅读源码的情况下采取下一步（补文件、改 manifest、拆篇或调上限）。
- **SC-004**: 在合法输入下，成书子命令执行后，源单篇 PDF 集合可被校验为未被工具就地修改（例如修改时间与大小与执行前一致，或文档约定的等价校验方式），同时各卷新合集文件被成功创建。
- **SC-005**: 对含至少两卷、每卷多篇、且带封面的样例工程，从初始化模板到生成卷集的完整流程，在普通桌面环境下可在一次交互会话内由单人完成（无外部在线依赖）。

## Assumptions

- 用户已理解 `sr_paperize` 产出单篇 PDF 与本功能「多篇合并成卷」的职责边界；二者可同时用于同一资料库但不互相改写对方产物。
- `max_pages_per_volume` 的默认 400 可被 manifest 覆盖；调高上限可能带来打印与阅读器性能压力，由用户自行权衡。
- 「打印目录页」的字体、边距与视觉样式由实现自由选择，只要目录语义与页码规则满足功能要求即可验收。
- 结构化计划默认文件名为 `plan.json`；若未来实现支持自定义文件名，规格以「可配置且默认同目录」为最低要求。
